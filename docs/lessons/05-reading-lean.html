Lesson 5

Reading Lean, part 1: functions and data

The first of three lessons on reading Lean 4, the language every file in this repository is written in. This one covers what every file is built from: functions, data types and pattern matching.

Lean 4 is two things at once: a functional programming language that compiles to native code, and a proof assistant. This lesson covers the programming language. Lesson 6 covers statements and theorems, just before the spec needs them, and Lesson 9 covers proofs, just before the first proof is taken apart. Every example is real code from the repository at stage-6, and the caption on each one links to it.

A first function

/-- `Error: {m}\n` (R60). Callers pass `sanitize`d text. -/
def errLine (m : String) : String := "Error: " ++ m ++ "\n"

Reading it:

  • /-- … -/ is a doc comment, attached to the definition after it. -- starts a line comment.
  • def errLine defines a function named errLine.
  • (m : String) is its one parameter: the name first, then a colon, then the type.
  • The : String after the parameters is the result type.
  • := means "is defined as". What follows is the body.
  • The body is a single expression, and its value is the result; there's no return. ++ joins two strings (or two lists).

In C++:

std::string errLine(std::string const& m) { return "Error: " + m + "\n"; }

A call has no parentheses or commas: the function is followed by its arguments, separated by spaces. errLine "no records" is "Error: no records\n". Parentheses are only for grouping. The program calls errLine (sanitize m), where (sanitize m) is one argument; without the parentheses, Lean would read it as errLine applied to two arguments, sanitize and m.

Conditions

def sgn (neg : Bool) : Int := if neg then -1 else 1

if … then … else … is an expression with a value, like C++'s ?:, so sgn true is −1 and sgn false is 1. Since it must have a value either way, the else can't be left out.

Several parameters

A function with several parameters lists them one after another. Parameters of the same type can share one pair of parentheses, so (y mo d : Nat) is three parameters, all of type Nat: a natural number, 0, 1, 2, and so on.

/-- "Tomorrow": the obvious successor of a date. -/
def nextDate (y mo d : Nat) : Nat × Nat × Nat :=
  if d < dim y mo then (y, mo, d + 1)
  else if mo < 12 then (y, mo + 1, 1)
  else (y + 1, 1, 1)
  • The result type Nat × Nat × Nat is a triple of natural numbers, and (y, mo, d + 1) is a value of that type.
  • dim y mo calls another function, dim (the number of days in month mo of year y), with two arguments.
  • else if chains work as in C++.
  • Written with arrows, nextDate's type is Nat → Nat → Nat → Nat × Nat × Nat: one arrow per parameter, and the last type is the result. Lean shows types this way in its messages, and Lesson 7 uses it for a function passed as an argument.

In C++:

std::tuple<unsigned, unsigned, unsigned> nextDate(unsigned y, unsigned mo, unsigned d) {
  if (d < dim(y, mo)) return {y, mo, d + 1};
  else if (mo < 12) return {y, mo + 1, 1};
  else return {y + 1, 1, 1};
}

Data: structure and inductive

A structure is a struct:

/-- An exact decimal `m / 10^e`. Deliberately the same shape as Lean's
`JsonNumber`, so JSON numbers convert without rounding (A3, R16). -/
structure Dec where
  m : Int
  e : Nat
  deriving Repr, DecidableEq, Inhabited

deriving asks the compiler to generate code: Repr is printing, DecidableEq is operator==, Inhabited is a default value.

Int is the integers (…, −2, −1, 0, 1, 2, …), and Nat is the natural numbers (0, 1, 2, …): whole numbers that can't be negative. Neither has fractions; that's Rat, in the table below. So m can be negative (−1.25 is ⟨-125, 2⟩), but e, the number of decimal places, can't, and the type says so: nothing has to check or prove that e is at least 0. Both are arbitrary precision. There's no overflow anywhere in this project, which removes a whole class of things to prove.

An inductive type is a tagged union, like std::variant with named alternatives that each carry their own fields:

/-- What the world answers to a GET. -/
inductive GetResult where
  | response (status : Nat) (body : String)
  | failed (msg : String)
  deriving Repr, DecidableEq

Each line starting with | is one alternative, called a constructor. The fields after a constructor's name are written like a function's parameters, each as (name : Type). So response carries two fields, a status that is a Nat and a body that is a String, while failed carries one, a msg. In C++ terms, response is roughly a struct { unsigned status; std::string body; }, and a GetResult holds either a response or a failed. Building a value looks like a function call: .response 200 "…" is a GetResult with status 200 and that body.

Lean's standard library defines more types the same way. Option, Except and List are themselves inductive types, and Array, pairs and Rat are structures. You'll see them as the types of fields, arguments and results. In this table, α, β and ε stand for any type, like T in a C++ template:

List α[a, b, c]; x :: xs is x in front of the list xsan immutable singly linked list
Array α#[a, b, c]std::vector<α>
α × β(a, b); for a pair p, p.1 and p.2 are its partsstd::pair<α, β>, with .first and .second

Taking values apart: match

alertNotice is the note printed after an alert is delivered. cfg.threshold is an Option Threshold: the threshold given on the command line, if there was one.

/-- The stderr note after a delivered alert (R53). -/
def alertNotice (cfg : Cfg) : String :=
  match cfg.threshold with
  | some th => "  ALERT: level >= " ++ th.text ++ " ft -> notified ntfy.sh/" ++ cfg.topic ++ "\n"
  | none => ""
  • match cfg.threshold with and the | lines below it are pattern matching: one line for each shape the value can have, with => before that case's result. If there's a threshold, some th matches and names it th; if not, none matches.
  • The compiler rejects a match that leaves a case out.
  • cfg.threshold, th.text and cfg.topic read fields of structures, as in C++.

In C++:

std::string alertNotice(Cfg const& cfg) {
  if (!cfg.threshold) return "";
  return "  ALERT: level >= " + cfg.threshold->text + " ft -> notified ntfy.sh/" + cfg.topic + "\n";
}

Lists, lambdas and dot calls

Patterns can also take a list apart. select picks the latest reading from a list:

/-- Keep the first reading seen with the latest instant: replace only on *strictly* later. -/
def select (rs : List Reading) : Option Reading :=
  match rs with
  | [] => none
  | r :: rest => some (rest.foldl (fun best x => if best.t < x.t then x else best) r)
  • [] matches the empty list, which gives none. r :: rest matches a list with first element r and the rest rest, which gives some (…).
  • rest.foldl f r is std::accumulate(rest.begin(), rest.end(), r, f). The dot works like a member call: rest is a List, so rest.foldl f r calls the function List.foldl with rest as its list argument. By the same rule, k.run w in later lessons is Prog.run k w when k is a Prog.
  • fun best x => … is a lambda: [](auto best, auto x) { … }.

In C++:

std::optional<Reading> select(std::list<Reading> const& rs) {
  if (rs.empty()) return std::nullopt;
  return std::accumulate(std::next(rs.begin()), rs.end(), rs.front(),
      [](Reading const& best, Reading const& x) { return best.t < x.t ? x : best; });
}

Pure, and total

Lean functions can't mutate anything or do I/O (except inside the IO type, which only Main.lean uses). They also have to be total: every case handled, and every call guaranteed to terminate. The compiler checks both. Code that can't be shown to terminate must be marked partial, and then you can't prove anything about it. In this repository exactly one function is partial: the shell's interpreter loop in Main.lean, which is outside the proofs anyway.

You'll also see do blocks with ← and let. They look imperative, but they're syntax for chaining Option/Except steps: let x ← step means "run step; if it failed, return the failure now; otherwise call the result x". It's like a chain of early returns on std::expected. Written inside an expression, (← step) does the same thing without naming the result. Inside a do block, pure x succeeds with x (like return x), and in an Except block, throw e fails with e.

Try it

Open LakeLevel/Impl/Calendar.lean and read digit? and hour12. You should be able to tell, with no help, that the first turns a digit character into its value (or none), and the second turns a 24-hour hour into a 12-hour one with AM or PM.
