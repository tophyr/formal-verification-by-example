Reading Lean, part 3: proofs and smaller syntax

The last of three lessons on reading Lean. It covers tactic proofs, which Lessons 10 and 11 take apart, and collects the smaller pieces of syntax that the rest of the lessons use.

This lesson builds on Lesson 5 (functions and data) and Lesson 6 (statements and theorems).

Tactics: writing a proof interactively

Writing out a whole proof by hand, as a term, gets tedious quickly. Instead, most proofs are written in tactic mode, entered with by. You see the current goal (what's left to prove), and each tactic transforms it, until nothing is left. It's like a debugger session where you step a proof instead of a program.

Here's a theorem about select, the function from Lesson 5 that picks the latest reading from a list:

/-- … and only fails on an empty list. -/
theorem select_none_iff (rs : List Reading) : select rs = none ↔ rs = [] := by
  cases rs <;> simp [select]

This is what Lean shows you (in an editor, it appears in a side panel as you move the cursor). At the start, above the line are the things you have; below ⊢ is what you must prove:

rs : List Reading
⊢ select rs = none ↔ rs = []

cases rs splits on the two shapes a list can have, leaving two goals:

case nil
⊢ select [] = none ↔ [] = []

case cons
head✝ : Reading
tail✝ : List Reading
⊢ select (head✝ :: tail✝) = none ↔ head✝ :: tail✝ = []

<;> means "then run the next tactic on every resulting goal". simp [select] unfolds the definition of select and simplifies: in the first case both sides are true; in the second, both sides are false (some … is never none, and a non-empty list is never []). No goals remain, so the proof is done. (The ✝ marks names Lean made up, which you can't refer to.)

The tactics you'll see most in this repository:

TacticWhat it does
intro hto prove "A → B", assume A (call it h) and prove B
exact e"here is exactly the thing you asked for"
cases x / rcases / obtain ⟨a, b⟩ := hsplit into one goal per shape of x; take apart an "and" or "exists"
by_cases h : Ptwo goals: one where P is true, one where it's false
inductionprove it for the empty case and for "one more", like a recursive function
unfold f / simp [f]replace f by its definition / rewrite and simplify with known facts; simp only [f, g] uses the listed facts and nothing else
rw [h]rewrite using an equation h : a = b: replace a by b
… at hadded to unfold, simp or rw: work on the hypothesis h instead of the goal
have h : P := proofprove P on the spot and add it to the hypotheses as h; without a name it's called this
subst hgiven h : x = e for a variable x, replace x by e everywhere
omegaa decision procedure: proves any true linear-arithmetic fact about integers (with +, * by constants, / and % by constants)
decideevaluates a statement that's decidable and finite, and checks it's true
refine ⟨?_, ?_⟩"I'll build this pair; give me a goal for each hole"
constructorsplit an "and" or "if and only if" into its parts
